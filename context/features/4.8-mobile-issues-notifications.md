# SeedNest Phase 4.8 — Mobile: Issues & Notifications Screens

## Context
You are working on **SeedNest**, a React Native + Expo app inside a monorepo.
- Path: `apps/mobile/`
- Navigation: Expo Router (file-based). Tabs in `apps/mobile/app/(tabs)/`.
- Auth: `useAuth()` returns `{ user, token }`.
- API base URL: `process.env.EXPO_PUBLIC_API_URL`
- State: React Query for server data, Zustand for local state.
- Icons: Lucide React Native or `@expo/vector-icons`.
- Phase 4.1 and 4.2 (issue + notification API) are complete.
- Phase 3.7 (mobile customer order screens) is complete.
- Keyboard handling: `react-native`'s `KeyboardAvoidingView`.

## Goal
Build the Issues tab (list, new issue form, issue detail/thread) and the Notifications screen accessible from the Account tab.

## Step 1: Issues tab — List screen

**File:** `apps/mobile/app/(tabs)/issues/index.tsx`

### Filter chips
A horizontal `ScrollView` (no scroll indicator) at the top with these tappable chips:

`All` | `Open` | `In Progress` | `Resolved` | `Closed`

Active chip: green background (`#2D6A4F`) + white text. Inactive: gray border + dark text.

Selecting a chip updates `filter` state and re-fetches.

### Issues FlatList
Fetch `GET /api/my-issues?status=[filter]&page=1&pageSize=30`.

**Per `IssueCard`:**
- **Title** (bold, 1 line truncated)
- **Type chip** (small colored pill):

| Type | Color |
|------|-------|
| `REPLACEMENT_REQUEST` | Orange |
| `QUERY` | Blue |
| `COMPLAINT` | Red |
| `GENERAL_REQUEST` | Gray |

- **Status chip** (small colored pill): Open=red, In Progress=blue, Resolved=green, Closed=gray.
- **Nursery name** (gray, `text-sm`)
- **Comment count**: "💬 N"
- **Last updated**: relative time string

Tap card → navigate to `/issues/[issueId]`.

### FAB (Floating Action Button)
Positioned `absolute` at `bottom: 24, right: 24`.
- Green circle (`#2D6A4F`), `+` icon (white, large).
- On press → navigate to `/issues/new`.

### Pull to refresh
`refreshControl` on `FlatList`.

### Loading & empty states
- Loading: `ActivityIndicator` centered.
- Empty: `MessageSquare` icon + "You haven't raised any issues yet. Tap + to get started."

## Step 2: Issues tab — New Issue screen

**File:** `apps/mobile/app/(tabs)/issues/new.tsx`

Wrap in `KeyboardAvoidingView behavior="padding"` with a `ScrollView` inside.

### Step-by-step fields (single scroll page, not a wizard)

**1. Select Nursery (required)**
Fetch manager's nurseries? No — fetch the customer's **recent orders** to derive nurseries.
Render a `FlatList` or `Picker` of nurseries derived from `GET /api/my-orders?pageSize=20`.
Extract unique nurseries from the orders. Tap to select (highlighted row).

**2. Link an Order (optional)**
After nursery is selected, show the orders for that nursery.
Render a horizontal scroll list of order cards:
- Order # (short), date, total.
Tap to select/deselect.

**3. Issue Type (required)**
Horizontal scroll row of 4 tappable cards:
- Each card: icon + label.

|------|----------|-------|

## Step 3: Issues tab — Issue Detail screen

**File:** `apps/mobile/app/(tabs)/issues/[issueId].tsx`

### Header
- Expo Router `Stack.Screen` options: `title` = issue title (truncated to 30 chars).
- Right header button: if `issue.status === 'RESOLVED'`, show a `RotateCcw` icon button → calls reopen API.

### Issue description card
`View` with light gray background, rounded corners, padding.
- "Issue Description" label (bold, small, gray, uppercase)
- Description text below

### Comment FlatList
Fetch `GET /api/my-issues/:id` for the full thread.

**Chat-style layout:**
- Customer messages (`comment.author.role === 'CUSTOMER'`): flush **right** side. Blue-tinted background (`#DBEAFE`). `borderRadius` with no bottom-right corner.
- Manager messages: flush **left** side. Green-tinted background (`#D1FAE5`). `borderRadius` with no bottom-left corner.

Per comment bubble:
- Author name (small, bold, above bubble)
- Body text
- Relative timestamp (tiny, gray, below bubble, opposite side)

**Inverted FlatList** (`inverted` prop): newest messages at the bottom. Pass `inverted={true}` and reverse the data array.

### Bottom reply bar
Fixed to the bottom of the screen (above the keyboard when open):

```tsx
<KeyboardAvoidingView behavior="padding" keyboardVerticalOffset={90}>
  <View style={styles.replyBar}>
    <TextInput
      style={styles.replyInput}
      placeholder="Write a reply..."
      value={replyText}
      onChangeText={setReplyText}
      multiline
      maxLength={2000}
    />
    <TouchableOpacity onPress={handleSend} disabled={!replyText.trim() || isSending}>
      <Send color={replyText.trim() ? '#2D6A4F' : '#ccc'} size={24} />
    </TouchableOpacity>
  </View>
</KeyboardAvoidingView>
```

On send:
1. Optimistically append the new message to the local comments list (add a temp comment with `isPending: true`).
2. Call `POST /api/my-issues/:id/comments`.
3. On success: invalidate the issue query, remove the temp comment.
4. On error: remove the temp comment, show an error snackbar.

### If status is `CLOSED`
- Show a banner at the top of the comment list: "This issue is closed and cannot be replied to."
- Disable the reply `TextInput` and Send button (gray out).

## Step 4: Notification badge component

**File:** `apps/mobile/components/NotificationBadge.tsx`

A small component that overlays a red count badge on a tab icon.

```tsx
interface NotificationBadgeProps {
  count: number;
}

export function NotificationBadge({ count }: NotificationBadgeProps) {
  if (count === 0) return null;
  return (
    <View style={{
      position: 'absolute',
      top: -4,
      right: -8,
      backgroundColor: '#EF4444',
      borderRadius: 9,
      minWidth: 18,
      height: 18,
      alignItems: 'center',
      justifyContent: 'center',
      paddingHorizontal: 3,
    }}>
      <Text style={{ color: 'white', fontSize: 10, fontWeight: 'bold' }}>
        {count > 99 ? '99+' : count}
      </Text>
    </View>
  );
}
```

## Step 6: Notifications screen (from Account tab)

**File:** `apps/mobile/app/(tabs)/account/notifications.tsx`

Register as a Stack screen accessible from the Account tab (add a "Notifications" row to the Account screen linking here — this was set up in Phase 3.8 Step 1, just ensure the link exists).

### Header
- Stack screen title: "Notifications"
- Right button: "Mark All Read" text button → calls `PATCH /api/notifications/mark-all-read`, shows snackbar "All notifications marked as read".

### Notifications FlatList
Fetch `GET /api/notifications?page=1&pageSize=50`.

**Per notification row:**
- Icon circle (36×36) based on type:

| Type | Icon | Color |
|------|------|-------|
| `NEW_ISSUE` | `AlertCircle` | Orange |
| `NEW_COMMENT` | `MessageCircle` | Blue |
| `LOW_STOCK` | `PackageOpen` | Red |
| `ORDER_UPDATE` | `ShoppingBag` | Green |

- **Title** (bold)
- **Message** (gray, 2-line truncated)
- **Time** (gray, `text-xs`, right-aligned) — relative string

**Unread indicator**: blue left border (`borderLeftWidth: 3, borderLeftColor: '#3B82F6'`) on unread rows. Read rows have no left border.

### Swipe to mark as read
Use `react-native-gesture-handler`'s `Swipeable` component.
Swipe **right** reveals a blue "Mark Read" action button.
On tap: call `PATCH /api/notifications/:id/read`, update row in local state.

### On row tap
Call mark-as-read (non-blocking) + navigate to the related entity:
- `NEW_ISSUE` / `NEW_COMMENT` → `/issues/[relatedId]`
- `LOW_STOCK` → Account → manager tools (or just show a snackbar: "Check your nursery seedlings")
- `ORDER_UPDATE` → `/orders/[relatedId]` (customer tab)

### Pull to refresh
`refreshControl` on `FlatList`.

### Empty state
Bell icon + "You're all caught up!"
